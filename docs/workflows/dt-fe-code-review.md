# 코드 리뷰 워크플로

## 호출과 범위

`dt-fe-code-review` 스킬을 호출하면 이 절차를 적용함. 리뷰 대상 PR, 브랜치 또는
diff가 명시되면 해당 대상을 기준으로 검토함. 대상이 없으면 현재 브랜치의
`develop` 대비 커밋 변경과 현재 작업 트리의 staged·unstaged·새 파일을 함께
검토함. 기준 브랜치와 실제 변경 범위를 먼저 기록하고 중복된 변경은 한 번만 검토함.

스킬 호출은 아래 로컬 보고서 작성까지 포함함. 사용자가 명시적으로 읽기 전용
검토를 요청하면 파일을 변경하지 않고 결과를 답변에 제공함. 대상이 불명확하거나
기준 브랜치를 확인할 수 없으면 범위를
추측하지 않고 사용자에게 확인함. `develop → main` 배포 PR은 이 일반 작업
워크플로의 대상이 아님.

## 검토

1. [헌법](../CONSTITUTION.md), [문서 지도](../README.md), 변경 영역의 상세 계약과
   실제 코드를 대조함. 리뷰 중 코드·Git index·외부 상태를 변경하지 않음.
2. PR이면 base·head와 실제 diff를 확인함. 브랜치이면 `develop`과의 분기점 및
   커밋 diff를 확인함. 작업 트리의 staged·unstaged diff와 새 파일도 별도로 확인함.
3. 기능·회귀·데이터 경계·접근성·테스트 누락 및 확정 컨벤션 위반을 검토함.
   기존 코드의 불일치를 새 규칙의 예외로 해석하지 않음.
4. 필요한 검증은 실행 가능 범위에서 수행하고 명령, 결과, 실행하지 못한 이유를
   구분함. 재현되지 않은 문제는 확정된 발견 사항으로 단정하지 않음.
5. 발견 사항은 영향과 우선순위에 따라 `상`·`중`·`하`·`컨벤션 위반`으로
   분류함. 각 항목에 파일·위치, 관찰 근거, 재현 조건 또는 확인 방법, 영향과
   권장 조치를 적음. 계약 위반은 영향도와 별개로 `컨벤션 위반`에 둠.

`상`은 기능·데이터·보안·핵심 사용자 흐름을 깨뜨리는 문제, `중`은 제한된 경로의
동작 오류나 유의미한 회귀 위험, `하`는 영향이 작은 결함이나 개선 사항으로
분류함. 확실하지 않은 사항은 근거와 미확인 조건을 표시함.

## 보고서

한국 시간 날짜로 루트 `review-report-yyyy-mm-dd.md`에 대상, 기준 커밋 또는
diff, 요약, 분류별 발견 사항, 실행한 검증과 미실행 검증, 잔여 위험을 기록함.
발견 사항이 없으면 그 사실과 검토 범위·한계를 명시함. 사용자에게도 주요 결과와
보고서 경로를 전달함.

같은 날 파일이 있으면 먼저 내용을 읽음. 이전 자동 보고서임을 확인할 수 있는
구간만 갱신함. 사용자 작성 내용이 있으면 보존하고 새 자동 보고서 구간을
추가하거나 갱신함. 자동 구간은 `<!-- dt-fe-code-review:start -->`와
`<!-- dt-fe-code-review:end -->`로 표시함. 구분이 불가능하면 덮어쓰지 않고
사용자에게 충돌을 알림.

보고서는 로컬 산출물임. 커밋·push 대상에서 제외하고, 리뷰 범위에도 포함하지
않음. PR을 준비할 때는 [PR 생성 워크플로](dt-fe-pull-request.md)의 중단 조건에
따라 결과를 처리함.
