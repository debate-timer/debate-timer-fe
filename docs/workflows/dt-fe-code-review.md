# 코드 리뷰 워크플로

## 호출과 범위

`dt-fe-code-review` 스킬을 호출하면 이 절차를 적용함. 리뷰 대상 PR, 브랜치 또는 diff가 명시되면 해당 대상을 기준으로 검토함. 대상이 없으면 현재 브랜치의 `develop` 대비 커밋 변경과 현재 작업 트리의 staged·unstaged·새 파일을 함께 검토함. 기준 브랜치와 실제 변경 범위를 먼저 기록하고 중복된 변경은 한 번만 검토함.

스킬 호출은 아래 로컬 보고서 작성까지 포함함. 사용자가 명시적으로 읽기 전용 검토를 요청하면 파일을 변경하지 않고 결과를 답변에 제공함. 대상이 불명확하거나 기준 브랜치를 확인할 수 없으면 범위를 추측하지 않고 사용자에게 확인함. `develop → main` 배포 PR은 이 일반 작업 워크플로의 대상이 아님.

## 검토

1. [헌법](../CONSTITUTION.md), [문서 지도](../README.md), 변경 영역의 상세 계약과 관련 위키·실제 코드를 대조함. 리뷰 중 코드·Git index·외부 상태를 변경하지 않음.
2. PR이면 base·head와 실제 diff를 확인함. 브랜치이면 `develop`과의 분기점 및 커밋 diff를 확인함. 작업 트리의 staged·unstaged diff와 새 파일도 별도로 확인함.
3. 기능·회귀·데이터 경계·접근성·테스트 누락 및 확정 컨벤션 위반을 검토함. 기존 코드의 불일치를 새 규칙의 예외로 해석하지 않음.
4. 필요한 검증은 실행 가능 범위에서 수행하고 명령, 결과, 실행하지 못한 이유를 구분함. 재현되지 않은 문제는 확정된 발견 사항으로 단정하지 않음.
5. 발견 사항은 영향과 우선순위에 따라 `상`·`중`·`하`·`컨벤션 위반`으로 분류함. 각 항목에 파일·위치, 관찰 근거, 재현 조건 또는 확인 방법, 영향과 권장 조치를 적음. 계약 위반은 영향도와 별개로 `컨벤션 위반`에 둠.

`상`은 기능·데이터·보안·핵심 사용자 흐름을 깨뜨리는 문제, `중`은 제한된 경로의 동작 오류나 유의미한 회귀 위험, `하`는 영향이 작은 결함이나 개선 사항으로 분류함. 확실하지 않은 사항은 근거와 미확인 조건을 표시함.

### 문서 갱신 검토

[문서 지도](../README.md#6-작업별-필수-읽기와-갱신)의 갱신 대상과 변경 전후의 동작·계약을 기준으로 `docs/` 내 소유 문서의 갱신 필요 여부를 판단함. 설명된 동작·책임·사용 방법·예외 조건 또는 경로·설정·검증 방법이 달라지면 갱신 대상임. 기존 계약을 유지하는 내부 변경이나 계약대로 동작을 복원하는 수정은 갱신이 불필요할 수 있음. 이동·삭제된 경로와 식별자는 문서의 참조도 확인함.

위키 영향은 [유지보수 기준](../wiki/maintenance.md)에 따라 검토함. 기능의 목적·도메인 개념·관계·상태·제품 조건·사용자 결과가 바뀌면 관련 기능 문서의 갱신과 일관성을 확인함. 사용 예시가 있으면 관련 정책과의 일관성을 검토하고, 예시에서 새 규칙을 정의하지 않았는지 확인함. 관련 위키가 없으면 기존 기술 계약을 기준으로 검토하고 문서화 공백을 기록하며, 부재만으로 전체 문서화를 요구하지 않음.

코드와 문서가 다르면 구현의 계약 위반인지, 의도한 계약 변경의 문서 누락인지 구분함. 의도가 불명확하면 판단을 보류하고 확인할 사항을 남김. 필요한 갱신이 diff에 반영되었는지 확인하고, 반영된 문서의 링크·예시·관련 문서와의 일관성은 [문서 작성 컨벤션](../conventions/docs.md)에 따라 검토함.

확정 정책·구현에서 확인한 사실·미확정 질문을 구분하고 근거와 적용 범위를 확인함. 문서 검증과 실제 동작 검증의 결과를 구분해 보고함.

정책 결정은 [결정 기록 조건](../wiki/maintenance.md#결정-기록을-남기는-조건)에 따라 기록 필요 여부를 판단함. 필요한 기록의 번호·근거·상태·대체 관계와 현행 정책의 연결을 확인하며, 모든 변경에 상세 결정 기록을 요구하지 않음.

## 보고서

한국 시간 날짜로 루트 `review-report-yyyy-mm-dd.md`에 대상, 기준 커밋 또는 diff, 요약, 분류별 발견 사항, 실행한 검증과 미실행 검증, 잔여 위험을 기록함. `문서 갱신 검토`에는 `갱신 필요`·`불필요`·`판단 보류`와 근거를 기록함. 갱신이 필요하면 대상 문서·절, 변경할 내용과 반영 여부를 적고 누락은 발견 사항에 포함함. 위키 영향도 같은 항목에 포함함. 판단 보류이면 차이·근거·확인 질문을, 관련 위키가 없으면 문서화 공백과 판단 근거를 기록함. 발견 사항이 없으면 그 사실과 검토 범위·한계를 명시함. 사용자에게도 주요 결과와 보고서 경로를 전달함.

같은 날 파일이 있으면 먼저 내용을 읽음. 이전 자동 보고서임을 확인할 수 있는 구간만 갱신함. 사용자 작성 내용이 있으면 보존하고 새 자동 보고서 구간을 추가하거나 갱신함. 자동 구간은 `<!-- dt-fe-code-review:start -->`와 `<!-- dt-fe-code-review:end -->`로 표시함. 구분이 불가능하면 덮어쓰지 않고 사용자에게 충돌을 알림.

보고서는 로컬 산출물임. 커밋·push 대상에서 제외하고, 리뷰 범위에도 포함하지 않음. PR을 준비할 때는 [PR 생성 워크플로](dt-fe-pull-request.md)의 중단 조건에 따라 결과를 처리함.
