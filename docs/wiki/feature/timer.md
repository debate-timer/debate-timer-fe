# 타이머 진행

## 목적과 제공 기능

사회자가 토론 테이블의 발언 순서를 따라 시간을 측정하고, 시작·일시정지·재개· 초기화·차례 이동·토론 종료를 조작하는 기능임. 일반·자유토론 타이머와 보조 작전 시간·답변시간 타이머, 별도 화면의 피드백 타이머를 다룸.

**지식 상태:** 명시한 확정 정책은 사용자가 미확정 질문 여섯 건에 답변한 [정책 승인 근거](#정책-승인-근거와-결정-이유)를 따름. 나머지 개념과 동작은 코드·테스트에서 확인한 사실이며 이번 승인 범위에 포함하지 않음. 승인된 정책과 현재 구현의 차이는 별도로 표시하며, 정책 승인으로 구현 완료를 주장하지 않음. 상태의 효력은 [위키 유지보수 기준](../maintenance.md#지식의-상태와-근거)을 따름.

조사 진입점은 [TimerPage](../../../src/page/TimerPage/TimerPage.tsx)임. 청중 공유·속기록 전사를 위한 녹음·투표는 이 문서의 설명 범위 밖이며, 마지막에 타이머와의 연결 경계만 기록함. 이 문서는 해당 기능의 정책을 정의하지 않음.

## 주요 개념과 관계

| 개념 | 의미 |
| --- | --- |
| 테이블 | 토론 정보와 순서가 있는 타임박스 목록을 제공하는 입력임 |
| 타임박스·차례 | 현재 표시하고 실행할 타이머의 종류·시간·발언 정보를 가진 항목임 |
| 팀당 전체 시간 | 자유토론에서 찬성·반대가 각각 보유한 누적 사용 가능 시간임 |
| 1회당 발언 시간 | 자유토론의 한 턴에 사용할 시간임. 설정값이 `null`이면 사용하지 않음 |
| 선택 진영 | 자유토론 조작의 대상인 찬성 또는 반대 진영임. 최초 선택은 찬성임 |
| 턴 시작 시간 | 차례 진입 또는 진영 전환 시 기록한 해당 팀의 전체·발언 시간임. 자유토론 초기화의 복원 기준임 |
| 시간 소진 | 타이머별로 초과 시간 표시 또는 정지를 일으키는 조건임. 차례 이동·토론 종료와 구분함 |

타이머 종류와 입력 필드는 [공용 타입](../../../src/types/type.ts), 차례와 선택 진영의 상태는 [페이지 상태 훅](../../../src/page/TimerPage/hooks/useTimerPageState.ts)이 근거임. 화면·훅의 기술적 책임은 [구조와 UI](../../architecture/structure-and-ui.md)를 따름.

## 기본 동작

1. 테이블 데이터를 읽고 첫 차례를 선택함. 조회 중에는 로딩 표시를, 조회 실패 시에는 재시도 가능한 오류 화면을 표시함.
2. 차례에 설정된 시간을 정지 상태로 준비함. 사용자가 재생 버튼이나 단축키로 시작하며, 일시정지 후 같은 조작으로 남은 시간부터 재개함.
3. 차례 이동은 사용자가 이전·다음 버튼으로 수행함. 시간이 소진되어도 자동으로 다음 차례나 종료 화면으로 넘어가지 않음.
4. 마지막 차례에는 다음 버튼 대신 종료 버튼을 표시함. 종료 조작은 종료 화면 이동 또는 게스트용 로그인·저장 안내로 연결함.

근거는 [메인 화면](../../../src/page/TimerPage/TimerPage.tsx), [페이지 상태 훅](../../../src/page/TimerPage/hooks/useTimerPageState.ts), [차례 조작](../../../src/page/TimerPage/components/RoundControlRow.tsx), [종료 분기](../../../src/page/TimerPage/hooks/useTimerPageModal.ts)임.

## 조건별 정책과 예외

각 절에서 **확정 정책**과 **구현에서 확인한 사실**을 구분함. 별도 표시가 없는 동작 설명은 구현에서 확인한 사실임. 승인 기록의 응답 번호는 이번 사용자 답변의 1~6번과 대응함.

### 일반 타이머

- `NORMAL` 차례는 설정된 `time`으로 준비하며 값이 `null`이면 0초로 준비함.
- 재생은 남은 시간이 `null`이 아니고 이미 실행 중이 아닐 때 시작함. 일시정지는 현재 표시 시간을 보존하며, 초기화는 정지 후 차례의 기본 시간으로 복원함.
- 0초에서 자동 정지하지 않음. 이후 남은 시간이 음수가 되고 화면에 음수 부호와 초과 시간을 표시함. 초과 상태에서도 일시정지·재개가 가능함.
- 실행 중 남은 시간은 목표 시각과 현재 시각의 차이로 계산함. 정지 시간은 계산에서 제외하고 재개 시 남은 시간으로 목표 시각을 다시 정함.

근거: [일반 타이머 계산](../../../src/page/TimerPage/hooks/useNormalTimer.ts), [일반 타이머 표시](../../../src/page/TimerPage/components/NormalTimer.tsx).

### 자유토론 타이머

**확정 정책 — 응답 4:** 완료는 팀당 전체 시간이 소진된 상태로 정의함. 1회당 발언 시간 소진은 이번 턴의 종료임. 팀당 시간이 남아 있다면 다음 턴의 발언이 가능하므로 완전한 발언 종료로 취급하지 않음.

**목표·구현 차이:** 현재 페이지 상태 훅은 발언 시간을 사용하는 경우 발언 시간 0초를 `isDone`으로 기록함. 승인된 완료 정의와 맞지 않으며 구현 보완이 필요함. 아래 목록은 이 차이를 포함한 현재 구현의 관찰 사실임.

- `TIME_BASED` 차례는 양 팀에 `timePerTeam`을 설정함. `timePerSpeaking`이 있으면 팀당 전체 시간과 1회당 발언 시간을 함께 표시·감소시키고, 없으면 전체 시간만 사용함. 선택하지 않은 진영의 마우스 조작부는 비활성화함.
- 재생 시 전체 시간이 `null`이거나 이미 실행 중이거나 완료 상태(`isDone`)이면 시작하지 않음. 일시정지·재개는 남은 시간을 사용함.
- 시간은 0초 아래로 내려가지 않음. 페이지 상태 훅은 전체 시간 또는 발언 시간이 0초이면 해당 타이머를 정지함. 1회당 발언 시간을 사용하면 선택 팀의 발언 시간 0초를, 사용하지 않으면 전체 시간 0초를 완료 상태로 기록함.
- 진영 전환은 현재 팀을 정지하고 상대 팀을 선택함. 상대 팀의 전체 시간은 보존하며 새 발언 시간은 전체 잔여 시간과 설정된 발언 시간 중 작은 값임. 넘기는 팀의 전체 시간이 소진된 경우에는 받는 팀의 전체 잔여 시간을 사용함.
- 전환 직전에 현재 팀이 실행 중이면 상대 팀도 시작을 시도하고, 정지 중이면 상대 팀도 정지 상태로 준비함. 상대 팀이 완료 상태이면 전환 버튼·Enter 조작을 통한 전환을 수행하지 않음.
- 초기화는 선택 팀을 정지하고 현재 턴 시작 시점의 전체·발언 시간으로 되돌림. 앞선 턴에서 사용한 시간까지 차례 최초 설정값으로 복원하는 동작은 아님.

### 차례 이동과 종료

**확정 정책 — 응답 3:** 게스트 종료 안내를 여는 순간 진행 중인 타이머를 일시정지해야 함. 이전에는 명확히 정하지 않았으며 이번 답변으로 새로 결정했음. 안내를 닫았을 때의 재개 방식까지 승인한 것으로 확대하지 않음.

**목표·구현 차이:** 현재 종료 처리에는 주 타이머 정지 호출이 없음. 안내가 같은 화면에서 열리는 게스트 흐름에 일시정지를 반영해야 함. 아래는 현재 구현임.

- 처음 차례에는 이전 버튼이 없고, 마지막 차례에는 종료 버튼이 있음. 시간 소진 여부와 관계없이 버튼으로 차례를 이동할 수 있음.
- 차례 진입 시 주 타이머들을 정리하고 해당 차례의 설정 시간으로 준비하며, 보조 작전 시간 표시를 닫음. 이전 차례로 돌아가도 진행하던 잔여 시간을 복원하지 않음. 진영 선택값은 차례 초기화 과정에서 찬성으로 재설정하지 않음.
- 이전·다음·종료 버튼은 500ms의 조작 대기 시간을 공유함. 다음 조작 직후 같은 위치에 나타난 종료 버튼이 연속 클릭으로 실행되는 것을 방지함.
- 종료 버튼은 전체 화면을 해제하고, 게스트이면 로그인·저장 안내를 열며 그 외에는 언어가 적용된 종료 화면으로 이동함. 종료 처리에는 주 타이머의 직접적인 정지 호출이 없으며, 화면을 떠날 때 훅이 타이머를 정리함.

### 보조 작전 시간

**확정 정책 — 응답 6:** 사용 가능 여부를 테이블 전체의 정확한 `speechType === '작전 시간'` 조건으로 판별하는 것은 의도된 규칙임. 해당 항목이 없으면 일반 타이머 화면에 보조 작전 시간 사용 버튼을 표시함. 표시 문자열의 띄어쓰기·번역을 정규화하는 별도 판별 방식은 이번 승인에 포함하지 않음.

- 테이블 전체에 `speechType`이 정확히 `'작전 시간'`인 항목이 없을 때 일반 타이머 화면에 사용 버튼을 표시함. 띄어쓰기나 번역을 정규화해서 검사하지 않음.
- 버튼을 누르면 주 타이머를 일시정지하고 별도 작전 시간 타이머를 표시함. 보조 시간은 처음에 미설정 상태이며 0초로 표시함. 30초·1분 단위로 더하거나 빼고, 양수일 때 재생할 수 있음.
- 실행 중 시간이 0초 이하가 되면 보조 타이머를 정지하고 닫음. 닫을 때 주 타이머를 자동 재개하지 않음. 주 타이머의 조작부를 잠그는 처리도 없음.

### 답변시간 타이머

- 주 타이머가 실행 중일 때 답변시간 버튼 또는 Shift로 시작함. 기본 보장 시간은 30초이며 설정에서 15·30·45·60초를 선택함.
- 주 타이머는 계속 진행하고 보조 타이머는 경과 시간을 셈. 다시 누르면 정지하고, 정지 상태에서 다시 누르면 초기화 후 표시를 해제함. 보장 시간에 도달해도 주 타이머를 정지시키지 않음.
- 주 타이머가 정지하거나 자유토론의 선택 진영이 바뀌면 답변시간 표시를 초기화함.

### 피드백 타이머

**확정 정책 — 응답 5:** 사용자는 피드백 타이머·타임박스를 테이블에 추가할 수 없음. 피드백 타이머는 토론 종료 후에만 진입하는 기능임. 공용 타입에 `FEEDBACK`이 존재한다는 이유로 사용자 구성 항목으로 허용하지 않음.

- 피드백은 별도 화면에서 0초로 시작하며 정지 중에만 ±1분·±5분으로 시간을 조절함. 음수로 내려가지 않고, 양수일 때만 재생함.
- 0초가 되면 자동 정지함. 초기화는 직전에 설정한 시간이 아닌 0초로 돌아감. 종료 화면으로 돌아가기 버튼은 화면 이동을 수행함.
- `FEEDBACK` 타입이 존재하지만 주 타이머 화면은 `NORMAL`·`TIME_BASED`만 렌더링함. 테이블에 `FEEDBACK`을 추가하는 경로로 해석하지 않음. 입력 제한과 토론 종료 전 직접 URL 접근의 차단 여부는 이번 문서 수정에서 검증하지 않았음.

### 단축키·시간 경고

**확정 정책 — 응답 1·2:** 자유토론은 A/L 키와 Enter 키를 통한 진영 전환을 지원하며 마우스 클릭으로는 진영을 전환할 수 없음. 타이머 화면에서 방향키로 차례를 이동할 수 없음. 방향키 이동은 과거에 가능했으나 합의로 막은 상태임.

**구현에서 확인한 사실:** A/L·Enter 처리 분기는 존재하고 마우스 전환 호출은 비활성화되어 있음. 단축키 훅의 A/L 비활성화 주석과 도움말의 마우스·방향키 이동 안내는 확정 정책과 맞지 않음.

- 주 화면에서 Space는 재생·일시정지, R은 초기화, Enter·숫자패드 Enter는 진영 전환을 처리함. 반복 키 입력은 무시함. 피드백 별도 화면에는 이 훅을 연결하지 않음.
- 실행 중 주 화면은 11~30초에서 경고, 0~10초에서 위험, 음수에서 초과 상태의 배경을 선택함. 정지 중에는 기본 배경임. 자유토론은 발언 시간이 있으면 그 값을, 없으면 팀당 전체 시간을 기준으로 함.
- 종소리 훅은 일반 타이머의 남은 시간과 차례의 종 설정을 사용함. 시작 후·종료 전· 종료 후의 설정 시점과 시간이 일치할 때 재생을 시도함. 자유토론·피드백 타이머에 같은 종소리 동작이 있다고 일반화하지 않음.

근거: [단축키](../../../src/page/TimerPage/hooks/useTimerHotkey.ts), [배경 상태](../../../src/page/TimerPage/hooks/useTimerBackground.ts), [종소리](../../../src/page/TimerPage/hooks/useBellSound.ts).

## 대표 사용 흐름·예시

현재 턴의 전체 시간이 94초, 발언 시간이 30초인 자유토론에서 5초를 사용하면 89초·25초가 남음. 이때 초기화하면 정지 상태의 94초·30초로 돌아감. 이는 차례 최초의 팀당 시간을 복원하는 동작과 다름. 근거는 [턴 초기화 테스트](../../../src/page/TimerPage/hooks/useTimeBasedTimer.test.ts)임.

## 정책 승인 근거와 결정 이유

[TIMER-DEC-001](../decisions/timer.md#timer-dec-001--기존-질문-여섯-건의-정책-확정)에 여섯 답변의 승인일·상황·결정 이유·적용 범위를 보존했음. 현행 정책은 위 동작 절에서 소유하며 결정의 상세 이력은 여기서 반복하지 않음.

### 구현 반영과 후속 확인

게스트 종료 일시정지·자유토론 완료 판정은 승인된 목표와 구현이 다름. 조작 안내와 주석의 불일치도 남아 있음. 각 절의 차이를 후속 구현·검증 대상으로 삼으며, 정책을 다시 미확정으로 돌리거나 현재 코드에 맞추어 완화하지 않음.

조작 안내 차이의 근거는 [도움말](../../../src/page/TimerPage/components/FirstUseToolTip.tsx), [단축키 훅](../../../src/page/TimerPage/hooks/useTimerHotkey.ts), [단축키 테스트](../../../src/page/TimerPage/hooks/useTimerHotkey.test.ts), [자유토론 UI](../../../src/page/TimerPage/components/TimeBasedTimer.tsx)임. 나머지 항목의 구현 근거는 각 동작 절에 연결했음.

게스트 종료 안내를 닫은 뒤의 재개 방식은 이번 승인 범위 밖임. 필요할 때 안내 열기 시 일시정지 정책과 구분하여 사용자 의도를 확인함.

## MP-03 답변 시간 제어 준비

답변 시간의 최초 켜짐·선택값 유지·실행 중 제한 변경·비활성화·단축키 차단 정책은 [토론 메뉴 위키](debate-controls.md#기능별-정책)를 따름. 상태 훅과 표시 입력을 준비했으며 메뉴에서의 실제 페이지 연결은 MP-04에서 수행함. 기존 일반·자유토론 진행 정책의 별도 목표 차이는 이번 준비 범위에서 변경하지 않음.
