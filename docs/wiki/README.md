# 정책·도메인 위키

이 위키는 기획·디자인·개발·리뷰에서 함께 사용할 기능의 목적, 도메인 개념과 관계, 제품 정책과 사용 예시를 연결함. 무엇을 제공하고 어떤 조건에서 어떻게 동작해야 하는지 이해하는 진입점임.

공용 안내·운영 기준·작성 양식과 아래 기능 문서를 제공함. 문서 추가를 개별 제품 정책의 승인으로 해석하지 않음.

## 기존 문서와의 역할

결정의 이유·승인 근거·대체 이력은 `decisions/`에서 관리함. 현재 기록은 [타이머 결정 기록](decisions/timer.md)에 있으며 [전역 설정 결정 기록](decisions/settings.md)에 MP-02의 정책 선택을 기록했음. 기능 문서는 현행 정책과 필요한 근거 링크를 유지하며 과거 결정의 상세 내용을 반복하지 않음.

위키는 제품의 의미·규칙·사용 사례를, `docs/architecture/`는 구현 계층과 통신·저장·복구의 기술 계약을, `docs/conventions/`는 작성 규칙을 다룸. 정확한 소유권은 [문서 작성 컨벤션](../conventions/docs.md#내용의-소유권)을 따름.

관련 기술 설명과 검증 근거는 필요한 부분에 링크로 연결함. 기존 아키텍처에 있는 계약은 실제 이전과 관련 참조 정리가 이루어지기 전까지 유지함.

## 기능별 기본 구조

```text
docs/wiki/
├── README.md            # 위키 안내와 기능별 읽기 경로
├── maintenance.md       # 지식 상태·근거·갱신 기준
├── templates/feature.md # 기능 문서 작성 양식
├── feature/
│   └── {기능}.md       # 현행 정책과 필요한 사용 예시·구현 차이
└── decisions/
    └── {기능}.md       # 조건에 해당하는 결정의 이유·승인 근거·대체 이력
```

위 구조는 향후 작성 위치를 안내하는 예시임. 기능은 페이지·컴포넌트 이름보다 사용자 과제와 제품 개념의 경계를 기준으로 나눔. 개별 기능 디렉터리 없이 `feature/{기능}.md` 한 파일에 설명과 정책을 작성하고, 이 진입점에 기능별 읽기 링크를 등록함. 빈 기능 문서는 미리 만들지 않음.

- 기능 문서 안에 목적·개념·기본 동작·조건별 정책·예외를 함께 둠. 필요한 경우 대표 사용 흐름·예시를 같은 문서의 선택적인 절로 설명함.
- 여러 기능에 걸친 사용 예시는 사용자 목적에 맞는 대표 기능 문서 한 곳에 두고 다른 기능의 정책을 링크함. 예시가 없는 기능에 작성을 강제하지 않음.
- 문서가 길어지면 [문서 작성 컨벤션](../conventions/docs.md#형식과-분량)에 따라 중복과 책임을 먼저 검토함.
- 결정 기록은 [유지보수 기준](maintenance.md#결정-기록을-남기는-조건)의 조건에 해당할 때 작성함. 단순 승인 확인은 기능 문서에 짧게 남길 수 있음.
- 공통 용어집은 공유할 실제 내용이 생기고 별도 관리가 필요할 때 분리함.

기능 문서가 아직 없을 때의 작업과 문서화 공백 처리는 [유지보수 기준](maintenance.md#작업과-리뷰에서의-적용)을 따름.
