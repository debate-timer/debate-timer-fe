# 기능 문서 작성 양식

`docs/wiki/feature/{기능}.md`를 작성할 때 아래 절 구조를 사용함. 실제 문서의 제목을 기능명으로 바꾸고, 작성 안내를 해당 기능에서 확인한 내용으로 대체함. 해당하지 않는 절은 생략하며 빈 항목을 채우기 위해 정책을 추측하지 않음.

지식 상태·근거·불일치 처리는 [유지보수 기준](../maintenance.md)을 적용함. 관련 링크는 작성한 문서 위치에서 연결되는지 확인함.

## 목적과 제공 기능

- 대상 사용자, 해결할 문제, 제공하는 동작과 적용 범위를 설명함.
- 이 기능과 인접 기능의 책임을 구분함.

## 주요 개념과 관계

- 제품에서 사용하는 용어·역할·대상의 의미와 관계를 설명함.
- 상태가 있다면 각 상태의 의미와 전이 조건을 적음.
- 공통 개념이 다른 문서에 있으면 짧게 언급하고 원문에 연결함.

## 기본 동작

- 시작 조건, 사용자 조작과 상태 변화, 종료 결과를 설명함.
- 구현 계층·통신·저장의 설명이 필요하면 해당 아키텍처 문서에 연결함.

## 조건별 정책과 예외

규칙마다 제목을 두고 다음 내용을 작성함. 짧은 규칙은 표나 문장으로 묶어도 됨.

| 항목             | 작성할 내용                                             |
| ---------------- | ------------------------------------------------------- |
| 지식 상태        | 확정 정책·구현에서 확인한 사실·미확정 질문 중 해당 상태 |
| 대상과 조건      | 누가, 언제, 어떤 상태에서 적용받는지                    |
| 동작과 결과      | 허용·거절·표시·기본값 등 조건에 따른 결과               |
| 예외와 복구      | 예외 조건과 그때의 동작·복구 경로                       |
| 근거와 적용 범위 | 승인 근거 또는 확인한 코드·테스트·재현 범위와 한계      |

승인된 목표와 현재 구현이 다르면 현재 확인한 상태를 구분해 적음.

## 대표 사용 흐름·예시 (선택)

- 정책만으로 이해하기 어려운 사용자 목적과 시작 조건을 적고, 주요 행동과 시스템 반응·결과를 순서대로 설명함. 필요한 예외 분기도 함께 설명함.
- 대표 사용 흐름이나 실패 시 영향이 큰 흐름을 우선함. 이용 근거가 없는 사용 빈도나 대표성 판단은 가설로 표시함.
- 관련 정책의 절을 연결하고 상세 조건·지식 상태·근거를 반복하지 않음. 미확정 결과를 보장된 동작처럼 쓰거나 예시에서 새 규칙을 정의하지 않음.
- 여러 기능에 걸친 흐름은 사용자 목적에 맞는 대표 기능 문서에서 설명하고 다른 기능의 정책을 연결함.
- 설명에 도움이 될 때만 작성하며 기본 동작과 같으면 생략함.

## 결정 근거와 미확정 질문

- [결정 기록 조건](../maintenance.md#결정-기록을-남기는-조건)에 해당하면 `docs/wiki/decisions/{기능}.md`에 이유·승인 근거·대체 이력을 기록하고 정책에서 해당 번호의 앵커로 연결함. 상세 내용은 이 문서에 반복하지 않음.
- 단순 승인 확인은 승인일·승인 주체·근거·범위를 짧게 기록함.
- 질문마다 확인한 사실, 모르는 부분과 다음 확인 방법을 구분함.
- 질문이 해소되면 정책과 근거에 반영하고 질문 형태로 누적하지 않음. 근거와 질문이 정책 옆에서 충분히 설명되면 이 절에서 반복하지 않음.

## 검증 근거와 한계

- 정책을 확인할 수 있는 테스트·Story·수동 검증 방법을 필요한 만큼 연결함.
- 검증되지 않은 항목은 그 상태와 한계를 적음. 테스트 실행 결과와 배포 이력은 기존 작업 기록에 남김.
