# 라이브 공유 타이머 동기화 규약

사회자(`TimerPage`)가 타이머 이벤트를 발행하고, 서버가 룸 채널(`/room/{roomId}`)로 중계하면, 청중(`AudienceSharePage`)이 받아 로컬에서 카운트다운합니다.
이 문서는 청중 화면이 사회자 타이머와 어긋나지 않도록 사회자·서버·청중이 지키는 규약을 정리합니다. (이슈 #494, Case 12~15)

## 메시지 구조

```ts
{
  eventType: 'NEXT' | 'BEFORE' | 'PLAY' | 'STOP' | 'RESET' | 'TEAM_SWITCH' | 'SYNC' | 'FINISHED' | 'ERROR';
  data: TimerDataPayload | null; // FINISHED와 ERROR는 null
  version?: number | null;       // 사회자가 채움
  serverTime?: number | null;    // 서버가 채움
}
```

- `data.remainingTime`은 **이벤트 발생 시점의 스냅샷**(정수 초, 올림)입니다.
- 사회자는 연결 중 5초마다 현재 상태를 `SYNC`로 발행합니다(heartbeat). 청중이 입장하면 서버가 `/chairman/{roomId}`로 요청해 즉시 `SYNC`를 받습니다.

## 1. 순서 보장과 중복 제거 — `version` (Case 13)

| 주체   | 역할                                                                                                                                                                                                                                                  |
| ------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 사회자 | 발행할 때마다 `version = max(직전 version + 1, Date.now())`. 새로고침해도 이전보다 큰 값이 됩니다. (`useChairmanSocket`)                                                                                                                              |
| 서버   | 룸별로 마지막으로 수락한 version보다 **같거나 작은** 이벤트는 중계하지 않고, 룸 상태(종료 여부)도 바꾸지 않습니다. version이 없는 이벤트는 하위 호환을 위해 통과시킵니다. 사회자가 `/chairman/{roomId}`를 구독하면(새 공유 세션) 기준을 초기화합니다. |
| 청중   | 마지막으로 반영한 version 이하의 메시지는 버립니다. 재연결하면 기준을 초기화하고, 곧바로 오는 `SYNC`로 현재 상태를 받습니다. (`useAudienceSocket`)                                                                                                    |

- 오래된 version이라 버린 메시지도 "사회자가 연결되어 있다"는 신호로는 사용합니다(`lastReceivedAt`).
- **한계**: 사회자가 시계가 느린 다른 기기로 옮겨 공유를 이어가면, 이미 연결된 청중은 그 기기의 version이 이전 값을 넘을 때까지 메시지를 버립니다. 청중이 새로고침하면 해소됩니다.

## 2. 네트워크 지연 보정 — `serverTime` (Case 12)

1. 서버가 이벤트를 중계할 때 `serverTime`(epoch ms)을 채웁니다.
2. 청중은 수신 시각 기준으로 `지연 = 수신 시각 - serverTime`을 계산합니다. (`getNetworkDelayMs`)
   - 음수이거나 1초(`MAX_NETWORK_DELAY_MS`)를 넘으면 실제 지연보다 **기기와 서버의 시계 차이**일 가능성이 크므로 보정하지 않습니다(0).
3. `syncedAt = 수신 시각 - 지연`을 "스냅샷이 유효했던 시각"으로 보고, 실행 중이면 목표 시각을 `syncedAt + remainingTime`으로 잡습니다. (`useAudienceShareState` → `useAudienceCountdown`)
   - 정지 상태, 정지 값에서 재개, 기준 시각이 미래이거나 2초 넘게 지난 경우는 보정하지 않습니다.
4. 사회자는 남은 시간을 **올림한 정수 초**로 보내므로 실행 중 스냅샷은 실제보다 최대 1초 큽니다. 실행 중 재동기화 차이가 1초 미만이면 기존 목표 시각과 새 목표 시각 중 **더 이른 쪽**을 택해, 5초 주기 SYNC마다 표시가 튀지 않게 합니다.

- 보정하지 않는 구간: 사회자 → 서버 구간 지연, 1초 이상의 비정상 지연.
- 청중 간 차이는 정수 초 표시 특성상 최대 1초까지 날 수 있습니다.

## 3. 0초(시간 종료) 판정 주체 (Case 14)

> **원칙: 시간 종료와 정지는 사회자가 이벤트(`STOP`/`SYNC`)로 확정합니다. 청중의 로컬 카운트다운과 0초 처리는 표시용입니다.**

| 타이머   | 사회자                                                                      | 청중                                                                                                         |
| -------- | --------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| 일반     | 0초를 지나 음수(초과 시간)로 계속 진행                                      | 동일하게 음수로 계속 표시                                                                                    |
| 자유토론 | 전체/1회 발언 시간이 0초가 되면 로컬에서 자동 정지 (이벤트는 발행하지 않음) | 0초에서 로컬로 멈춰 표시(`isLocallyStopped`), 다음 heartbeat `SYNC`(최대 5초 뒤)의 `isRunning: false`로 확정 |

- 청중 코드에서 로컬 0초 도달을 근거로 순서 이동·종료 화면 전환 같은 **상태 변경을 하지 않습니다.** 이런 동작은 사회자 이벤트를 받았을 때만 합니다.
- 사회자 탭이 백그라운드로 가면 브라우저가 타이머를 늦춰 heartbeat가 늦어질 수 있습니다. 청중은 15초(`CHAIRMAN_ABSENT_TIMEOUT_MS`) 동안 메시지가 없으면 "사회자 연결 끊김"으로 보고 카운트다운을 멈춥니다.
- 청중이 사회자보다 먼저 들어와 사회자 메시지를 한 번도 받지 못했다면, 서버의 `CHAIRMAN_ABSENT` 알림이나 15초 경과와 관계없이 "토론 시작을 대기 중입니다." 화면을 유지합니다. 사회자가 공유를 시작해 첫 `SYNC`가 오면 타이머 화면으로 바뀝니다. "사회자 연결 끊김" 안내는 사회자 메시지를 한 번이라도 받은 뒤에만 표시합니다.

## 4. 빠른 연타 (Case 15)

- 이전/다음 차례·토론 종료 버튼은 한 번 누르면 500ms(`ROUND_CONTROL_COOLDOWN_MS`) 동안 다시 누를 수 없습니다. 세 버튼이 대기 시간을 공유하므로, 마지막 직전 차례에서 다음 차례를 더블클릭해도 같은 자리에 나타난 토론 종료가 눌리지 않습니다. (`RoundControlRow`)
- 핫키를 길게 눌러 생기는 반복 입력(`event.repeat`)은 무시합니다. (`useTimerHotkey`)
- **서버 검증은 두지 않습니다.** 서버는 룸의 현재 순서를 알지 못하는 중계자이고, 의도적으로 빠르게 넘긴 것과 실수를 구분할 수 없습니다. `NEXT`/`BEFORE`는 이동 전 순서(`sequence`)를 담은 절대값이라 같은 이벤트가 중복 도착해도 청중 결과는 같고, 오래된 이벤트는 `version` 검증이 막습니다.

## 5. 재연결과 백그라운드 탭 (Case 7, 9)

### 재연결 시도 소진 (Case 7)

- 소켓은 끊기면 자동으로 재연결합니다. (풀 지터 + 지수 백오프, 대기 상한 30초, `SocketManager`)
  - 청중: 최대 3회까지 재시도합니다. 청중은 수가 많아 동시 재접속 부담이 큽니다.
  - 사회자: 횟수 제한 없이 첫 끊김부터 2분 동안 재시도합니다. (`useChairmanSocket`) 서버는 활성 사회자 등록을 메모리로만 들고 있어, 사회자 연결이 끊긴 채 남으면 청중이 새로고침해도 복구되지 않기 때문입니다. 2분 안에 서버가 살아나면 재구독으로 활성 사회자가 다시 등록되고, 곧바로 현재 상태를 공유해 청중도 함께 복구됩니다.
- 재시도 조건을 넘기면 `SOCKET_RETRY_EXHAUSTED` 오류와 함께 클라이언트를 완전히 닫습니다. 이 상태는 자동으로 복구되지 않습니다.
- **청중**: 이미 타이머를 보고 있었다면 화면을 지우지 않고, 마지막 상태를 남긴 채 새로고침 안내 오버레이를 덮습니다. 카운트다운은 사회자 부재와 같은 방식으로 마지막 값에서 멈춥니다. 한 번도 타이머를 표시하지 못했다면 기존 오류 화면을 씁니다. (`useAudienceShareState`, `ConnectionLostNotice`)
- **사회자**: 라이브 공유 모달에 연결이 끊겼다는 안내와 새로고침 안내를 표시합니다. (`LiveShareModal`)
- **수동 재연결 버튼은 두지 않습니다.** 서버 여유가 넉넉하지 않아 재연결 시점을 사용자에게 맡기지 않고, 새로고침으로 상태를 처음부터 다시 맞추게 합니다.

### 백그라운드 탭 (Case 9)

브라우저는 백그라운드 탭의 타이머와 네트워크를 억제합니다. 그래서 탭이 돌아오는 시점(`visibilitychange`)에 양쪽 모두 상태를 다시 맞춥니다. (`useDocumentVisibility`)

| 주체   | 복귀 시 동작                                                                                                                                                       |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 사회자 | 연결이 살아 있으면 heartbeat를 기다리지 않고 즉시 `SYNC`를 발행합니다. 연결이 끊겨 있었다면 공유를 다시 시작합니다. (최소 간격 1초)                                |
| 청중   | 연결이 살아 있으면 `/room/{roomId}`를 다시 구독합니다. 서버는 청중이 구독할 때 사회자에게 상태 공유를 요청하므로, 재구독이 곧 재동기화 요청입니다. (최소 간격 3초) |
| 청중   | 연결이 끊겨 있었다면 다시 연결합니다.                                                                                                                              |

- 사회자 탭이 백그라운드에 있는 동안에는 heartbeat가 늦어져 청중이 "사회자 연결 끊김"으로 볼 수 있습니다. 복귀 즉시 `SYNC`를 보내 이 오해를 빠르게 풉니다.
- 청중이 여럿 동시에 복귀하면 상태 공유 요청이 그만큼 늘어납니다. 서버는 룸별로 요청 최소 간격(500ms)을 두어 사회자의 발행이 증폭되지 않게 합니다. 버려진 요청은 직전 요청에 대한 `SYNC` 브로드캐스트가 대신합니다.
