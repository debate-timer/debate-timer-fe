# 공통 디자인 컨벤션

## 적용 범위

이 문서는 모든 컴포넌트에 적용할 수 있는 공통 규칙만 포함함. 개별 명세와 문서의 책임 경계는 [문서 작성 컨벤션](docs.md#내용의-소유권)을 따름.

페이지·공용 UI·기능 전용 UI의 시각 기준을 소유함. 신규 UI와 실질적으로 변경하는 UI는 이 기준에 맞춰 설계하며, 기존 화면의 차이를 새로운 디자인의 예외로 해석하지 않음. 같은 역할은 같은 기준을 사용하고, 사용 목적이 다르면 필요한 변형을 허용함. 변형은 기본 기준과 다른 이유·적용 범위를 간단히 기록하며, 화면마다 독립적인 시안을 만들지 않음.

UI 책임과 재사용 범위는 [구조와 UI](../architecture/structure-and-ui.md),
스타일 구현·접근성·사용자 문구는 [React·UI](react-and-ui.md), 테스트와 시각
검증 절차는 [테스트·Storybook](testing-and-storybook.md)이 소유함.

## 기본 방향과 변형

흰 바탕·어두운 글자·노랑 강조를 기본으로 밝고 명확한 화면을 구성함.

일반 UI는 여유 있는 간격과 충분한 조작 영역을 기본으로 함. 정보량이 많은 곳은
조밀한 변형을 허용하되, 글자와 조작 영역을 무리하게 줄여 밀도를 높이지 않음.
원거리에서 확인하는 숫자, 긴 글을 읽는 영역, 소개용 큰 문구처럼 목적이 다른
표현은 그 목적에 맞게 조정함. 변형을 위한 크기 종류를 미리 늘리지 않음.

## 색상과 강조

### 브랜드·진영색

[index.css](../../src/index.css)에 정의된 다음 색상을 사용함.

| 역할        | 이름          | 값        |
| ----------- | ------------- | --------- |
| 브랜드 강조 | `brand`       | `#FECD4C` |
| 브랜드 호버 | `brand-hover` | `#DBA822` |
| 찬성 진영   | `stance-blue` | `#1E91D6` |
| 반대 진영   | `stance-red`  | `#E14666` |

### 중립·오류색

중립색은 Tailwind CSS 4의 `neutral`, 오류색은 `red` 기본 팔레트를 사용함. 배경·본문·보조 설명·경계·비활성 등 의미에 맞는 단계를 사용하고, 모든 단계의 사용처를 미리 정하지 않음. 흰색은 기본 면으로 사용하며 회색 계열을 화면마다 따로 선택하지 않음.

일반적인 주요 행동과 선택 강조는 브랜드 노랑을 중심으로 구성함. 컴포넌트마다
보라·파랑 등 별도의 일반 선택색을 만들지 않음. 진영과 오류처럼 별도 의미가
있는 색은 해당 역할에 사용하며, 색만으로 상태를 전달하지 않음. 비활성·미선택·
호버는 서로 다른 상태로 구분함.

색상 단계는 실제 배경과 글자·아이콘의 조합에서 읽기 쉬운지 확인해 선택함. 기존 UI에 남아 있는 `default-*`·`semantic-*` 등 구형 클래스는 신규·수정 코드에서 사용하지 않으며, 추후 별도 작업을 통해 구형 클래스를 신형 클래스로 다듬는 작업이 완료되었을 때 이 문장을 제거함.

## 타이포그래피

### 역할별 기본 스타일

글꼴은 현재 전역 Pretendard 계열과 대체 글꼴 순서를 상속함. 자간은 기본값을
사용함. 글자 크기·굵기·행간을 하나의 역할별 스타일로 다루고, 색상은 강조·
오류 등 문맥에 따라 별도로 선택함.

| 역할     | 용도                  | 클래스             | 크기 | 굵기 | 행간 |
| -------- | --------------------- | ------------------ | ---- | ---- | ---- |
| Headline | 화면의 대표 제목      | `text-ui-headline` | 28px | 700  | 36px |
| Title    | 구역·내용 묶음의 제목 | `text-ui-title`    | 24px | 600  | 32px |
| Body     | 본문                  | `text-ui-body`     | 16px | 400  | 24px |
| Label    | 짧은 조작·항목 이름   | `text-ui-label`    | 16px | 600  | 24px |
| Caption  | 보조 설명             | `text-ui-caption`  | 14px | 400  | 20px |

제목은 크기와 굵기로 분명히 드러내며, 본문과 보조 설명은 읽기 편한 차이를 둠. 역할마다 기본 스타일 하나로 시작하고 실제 필요가 있을 때만 변형을 추가함. 모든 역할에 작은·중간·큰 단계를 만들지 않음.

### 역할 선택과 기존 선택자의 차이

화면 대표 제목에는 Headline, 그 아래 구역 제목에는 Title을 선택함. 본문은
Body, 버튼·항목의 짧은 이름은 Label, 부가 설명은 Caption을 기본으로 함.
색이나 크기만 보고 역할을 선택하지 않음.

시각 역할을 HTML 요소와 일대일로 연결하지 않음. 예를 들어 Title 스타일의
HTML 제목 수준은 문서 구조에 따라 결정하며, Label 스타일이 HTML `label`
요소만을 뜻하지 않음. 의미 구조는 [React·UI](react-and-ui.md)의 계약을 따름.

글자 역할에는 위 표의 `text-ui-*`를 사용함. 기존 코드의 `.text-title`·`.text-body` 등 크기만 선언된 구형 클래스는 신규·수정 코드에서 사용하지 않으며, 추후 별도 작업을 통해 구형 클래스를 신형 클래스로 다듬는 작업이 완료되었을 때 이 문장을 제거함. 타이머 수치나 홍보 문구의 변형도 일반 역할의 기본값을 바꾸는 근거로 삼지 않음.

### 사용과 사양 동기화

[index.css](../../src/index.css)의 `@theme`에 `--text-ui-{역할}`과 이에 대응하는
`--line-height`·`--font-weight` 속성을 정의함. Tailwind가 이를 묶어 위 클래스와
`md:text-ui-title` 같은 화면 조건 조합을 생성함. 글꼴·색·자간은 역할에 고정하지
않으며, 선택한 역할의 크기·굵기·행간을 개별 utility로 임의 덮어쓰지 않음.
변형이 필요하면 이 문서의 공통 변형 원칙을 적용함.

```tsx
<h1 className="text-ui-headline">{t('토론 기록')}</h1>
<p className="text-ui-body text-neutral-700">{description}</p>
```

**타이포그래피 사양을 변경할 때는 이 문서의 표와 `src/index.css`의 대응
`@theme` 정의를 반드시 같은 변경에서 갱신함.** 역할·클래스명을 추가·변경·삭제하면
사용처와 디자인 샘플 Story도
함께 갱신함. 값만 바뀌는 경우 Story는 같은 클래스를 통해 변경값을 반영함.
문서의 사양과 실제 생성 CSS의 크기·굵기·행간을 대조하고 lint·build로 검증함. 개별 조작에만 쓰는 글자 변형은 해당 선언의 JSDoc과 CSS 정의를 함께 갱신함.

## 형태·영역 구분·행동의 위계

### 폼 입력 영역

텍스트 입력과 선택 입력의 입력 영역은 `src/index.css`의 `form-control-border` utility를 공유함. 모서리는 8px, 테두리는 2px이며 기본 `neutral-300`, 호버 `neutral-400`, 비활성 `neutral-200`을 사용함. 포커스 또는 드롭다운 열림(`aria-expanded="true"`)에는 `brand-hover` 테두리와 2px `brand/20` 링을 함께 표시함. 오류(`aria-invalid="true"`)는 `red-500` 테두리와 포커스 시 `red-500/20` 링을 사용하며 비활성 상태가 우선함. 높이·배경·타이포그래피·내부 배치는 각 컴포넌트가 소유함.

### 형태와 강조

주요 행동은 브랜드 강조, 차분한 보조 조작은 중립색 면, 존재감을 분명히 보여줄 대안 행동은 테두리 등으로 구분함. 색상·크기·형태는 별도로 판단하며 문맥의 행동 중요도를 기준으로 선택함. 큰 조작 문구는 제목 역할과 분리하고 아이콘·문구 크기를 항상 일치시키는 전역 규칙은 두지 않음.

둥근 인상을 유지하되 작은 요소와 큰 면의 모서리를 소수 단계로 구분함.
완전히 둥근 형태는 강조·조작 등 역할이 분명한 곳에 사용함. 컴포넌트마다
독립적인 곡률을 만들거나 모든 요소를 같은 곡률로 맞추지 않음.

버튼은 공통 글자·형태·상태 표현 체계 안에서 행동의 중요도와 의미에 따라
강조 수준을 구분함. 주요 행동은 브랜드 강조, 보조 행동은 약한 면·테두리 등으로
위계를 만듦. CTA와 확인·취소라는 이름만으로 서로 독립적인 시안을 만들지 않음.
확인 동작도 해당 맥락의 주요 행동이면 같은 주요 강조 원칙을 사용함.

영역 구분은 여백만으로 충분한지 먼저 확인하며 필요할 때 배경·테두리를 추가함. 상호작용 강조는 배경·테두리 변화를 우선함. 그림자는 떠 있는 면 등
깊이가 필요한 경우에 사용함. 확대·색 발광은 일반 강조 수단으로 널리 사용하지
않고 목적이 분명한 경우에 제한함. 각 컴포넌트의 치수·곡률·그림자 수치를 모두
공통 지침으로 고정하지 않음.

## 공간 제약과 움직임

화면이 좁거나 문구가 길면 정보와 조작의 가독성을 우선함. 줄바꿈·재배치·영역
확장·필요한 스크롤로 대응하고 한 화면에 넣기 위해 글자·조작 영역을 무리하게
축소하지 않음. 요약 영역에서 말줄임을 사용하면 펼침·상세 이동 등 전체 내용을
확인할 경로를 둠. 한국어·영어의 길이 차이와 좁거나 낮은 화면도 함께 확인함.
화면 조건의 정의는 [React·UI](react-and-ui.md#스타일과-접근성)를 따름.

움직임은 상태 변화와 동작 결과를 이해시키는 짧은 전환을 기본으로 함. 장식적·
반복적 움직임은 제한하고, 필요한 진행 표시에는 움직임 감소 설정에서 의미를
유지하는 대체 표현을 제공함. 모든 컴포넌트의 전환 시간을 하나의 수치로
고정하지 않음.

### 조작 영역과 상태의 적용 범위

아이콘·호버 배경·클릭 영역을 각각 검토하며 표시를 작게 만들 때 조작 영역까지 함께 줄이지 않음. 조밀한 목록은 주변 간격과 오조작 가능성을 확인함. 입력창 포커스에는 공통 브랜드 테두리·링을, 버튼·체크박스·라디오에는 어두운 outline을 사용함. 드롭다운 항목은 선택 배경과 구분되는 브랜드 outline을 사용함. 입력창의 이중 표현을 모든 조작에 일괄 적용하지 않음.

오류 테두리·메시지는 오류를 전달하고 지우기 같은 보조 조작은 자체 중립색을 유지함. 아이콘을 모든 곳에서 같은 색상 단계로 고정하거나 테두리 색상에 자동 종속시키지 않음. 흰 체크 표시와 브랜드 배경 등 선택 표현은 실제 크기·배경·비활성 상태에서 구분 가능성을 확인함.
