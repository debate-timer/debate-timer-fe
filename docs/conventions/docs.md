# 문서 작성 컨벤션

## 적용 범위

이 문서는 `docs/**/*.md`, 루트 `AGENTS.md`·`README.md`, `.github`의 이슈·PR
Markdown 템플릿에 적용함.

## 형식과 분량

- 문서는 Markdown으로 작성함.
- 빈 줄, 표, 코드 블록, front matter를 포함한 물리적 줄 수를 셈.
- 모든 적용 문서는 500줄을 넘기지 않음. `docs/README.md` 이외의 문서는 300줄
  이하를 권장함.
- 300줄을 넘으면 중복을 먼저 제거하고, 서로 다른 독자 과제나 책임이 섞여 있을
  때만 분할함. 분량을 채우려고 내용을 추가하지 않음.
- 문장형 어미 대신 `~함`, `~했음`, `~임` 등 명사형 어미로 종결함. 코드, 명령어,
  고유명사, 직접 인용은 원형을 유지함.

## 내용의 소유권

- 원칙은 [헌법](../CONSTITUTION.md), 기술 지도와 읽기 경로는
  [문서 지도](../README.md), 정확한 계약은 해당 상세 문서 한 곳에 기록함.
- 다른 문서에서 필요한 규칙은 짧게 언급하고 상대 링크로 원본에 연결함. 같은
  규칙·예시·근거를 반복하지 않음.
- 작업 수행에 없으면 안 되는 내용만 유지함. 필수 내용으로 이해할 수 있는 배경,
  장황한 예시, 반복 설명은 생략함.
- 호출 방법, 처리 흐름, 책임 경계, 예외 조건, 검증 방법의 이해에 필요한 설명은
  유지함.
- 규칙의 현재 코드 근거와 적용 범위를 명시함. 구현보다 앞선 목표 규칙은 `목표`로
  표시하고 현재 상태와 구분함.

## 링크와 갱신

- 저장소 내부 문서는 상대 링크를 사용하고 링크 대상이 실제로 있는지 확인함.
- 코드 경로는 실제 파일·디렉터리와 대조함. 파일 이동 시 소유 문서와 진입점의
  링크를 함께 갱신함.
- 상세 계약을 변경할 때 그 문서의 소유 범위만 고치고, 필요하면
  [문서 지도](../README.md)의 경로·요약·읽기 표를 갱신함.
- 상세 문서 사이 또는 요약과 상세 계약 사이의 불일치는 임의로 선택하지 않고 문서
  오류로 수정함.
